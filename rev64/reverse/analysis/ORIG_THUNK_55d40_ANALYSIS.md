## 二、★ 评分逻辑定位结论 (诚实边界)

### 未定位
- 0x55d40 区 75 thunk 的 41 个 bl 目标中, **无明确 AI 评分特征**:
  - 无 `movw r0, #1000/900/800/700/2/1` 常量比较
  - 无 rank 比较分支 (cmp rX, #rank)
  - 高频目标多为析构/setter/虚函数分发
- **64 位 src_rs ai_score 评分表 (1000 吃子/900 同级/800 炸弹/700 工兵/2 空移/1 送死) 在 32 位 0x55d40 区未找到对应实现**

### 可能原因
1. **评分逻辑不在 0x55d40 区** — 64 位注释 "0x39f20/0x55d40 单步贪心" 可能是**语义对齐**, 非地址对齐
2. **评分在 0x39f20 区 (走子执行器)** — 需反汇编 0x39f20 附近 (原版 .text)
3. **评分分散在多个 handler** — 单步贪心 = 无集中评分表, 各 handler 内联

### 64 位 src_rs 对照 (rules.c:1209)
```c
// ai_score: 1000 吃子 / 900 同级 / 800 炸弹 / 700 工兵挖雷 / 2 空移 / 1 送死 / -1 旗雷 / -2 空源
// 注释: "对齐原版 0x39f20/0x55d40 单步贪心无价值维度"
//      "原版无 ai_value 子力表, 兄弟实现 game_logic.c:534 ai_value 为手写路线自有设计"
```
- **结论**: 64 位 ai_score 是**简化贪心**, 原版可能更简单 (无价值维度)
- 但 32 位 0x55d40 区 41 目标中**未实证** "无价值维度" — 需继续逆向 0x39f20 区

## 四、教训固化

### 4.1 thunk 收表方法 (可复用)
```bash
# 提取地址范围 bl 目标
arm-none-eabi-objdump -d so | grep -oP '^[0-9a-f]{5,6}:\s+[0-9a-f]{4}\s+\w+\s+(bl|b)\s+[0-9a-f]+'
# 按范围过滤 + 统计独立目标
```

### 4.2 评分逻辑识别特征
```
AI 评分代码特征 (未找到):
  - 常量 1000/900/800/700/2/1 (movw/movs)
  - rank 比较 (cmp rX, #N, N=rank 值)
  - 分支: 吃子/同级/炸弹/工兵/空移

thunk 区高频目标特征 (实际找到):
  - ldr [r0, #offset] + cmp #0 (判空)
  - blx vtable (虚函数)
  - 大栈帧 0x108 (复杂业务)
  → 多为析构/setter, 非评分
```
