## 一、0xb67ec 区实证 (★ 新发现)

### 函数特征
- 0xb67ec: 4 指令 thunk (`movs r2, #1; movs r3, #86; strb r2, [r0, r3]; bx lr`)
  - **对象字段 86 (0x56) 置 1** = 标志位 setter (可能是 "已走子" / "已吃子" 标记)
- 0xb67f4: 5 指令 thunk (调 0xbd550)
- 0xb6804: 数据区 (ldrsb r4, [r0, r2])

### 推测功能
- **0xb67ec = 标志位 setter** (对象 +86 置 1), 被 0x39f20 调用 → 走子后标记状态

## 二、0xb6808 函数实证 (★ 走子验证核心)

### 函数特征
- 大小: ~33 指令 (短函数)
- 参数: r0 (from?) / r1 (to?) / r4 (rank/side?)

### 关键指令 (实证)
```
b6810:  cmp  r1, #7          ← to 边界检查 (<7?)
b6812:  bhi  b681e          ← 越界分支
b6814:  movs r2, #1         ← 合法标志
b6818:  movs r3, #134       ← 对象偏移 134
b681e:  movs r3, #196       ← 对象偏移 196
b6822:  cmp  r0, #0         ← from 判空
b6826:  cmp  r4, #2         ← rank == 2?
b682a:  cmp  r4, #7         ← rank == 7?
b682e:  cmp  r4, #1         ← rank == 1?
b6832:  movs r3, #192       ← 对象偏移 192
```

### 功能实证 (★ 修正 "无 rank 比较" 结论)
- **存在 rank 比较**: `cmp r4, #2/#7/#1` = 棋子等级判定
- **rank 编码推测**: 1/2/7 = 具体棋子等级 (军棋 rank 0-9?)
- **边界检查**: `cmp r1, #7` = 目标格 < 7 (小棋盘?)
- **对象偏移**: 134/192/196 = 状态字段 (合法标志/结果码)

### ★ 对 64 位 src_rs 的启示
| 32 位实证 | 64 位 src_rs 对应 | 状态 |
|-----------|-------------------|------|
| `cmp r1, #7` 边界检查 | jq_can_move 界检查 (rules.c:458) | 需对照 (7 vs N_CELLS) |
| `cmp r4, #2/#7/#1` rank 判定 | rank_of (junqi.h) | 需对照 (rank 编码是否一致) |
| 对象 +134/+192/+196 字段 | jq_state 结构体偏移 | 需对照 (布局是否一致) |

## 四、64 位对照任务 (给正向会话)

### 需对照项 (AUD_ALIGN_R17 输入)
| 32 位实证 | 64 位对应 | 风险 |
|-----------|----------|------|
| `cmp r1, #7` 边界 | rules.c jq_can_move 界检查 | 中 (7 是否 = 列数?) |
| `cmp r4, #2/#7/#1` rank | junqi.h rank_of 编码 | 高 (rank 编码不一致 = 走子规则错) |
| 对象 +134/+192/+196 | jq_state 字段布局 | 低 (行为对齐即可) |

### 建议动作 (正向会话)
1. 提取 32 位 0xb6808 的 rank 比较值 (1/2/7) + 边界值 (7)
2. 对照 64 位 rules.c jq_can_move 的 rank 判定逻辑
3. 若 rank 编码不一致 → 修 64 位 (或确认 32 位 rank 编码 = 红方 +0xc 后值)

## 五、教训固化

### 5.1 短函数易漏 (本轮 0xb6808 教训)
```
前轮 "0x55d40 区 41 目标无 rank 比较" 结论漏了 0xb6808
  - 0xb6808 不在 0x55d40 thunk 区, 在 0xb67ec 区 (走子验证)
  - 教训: "无评分" 结论需覆盖所有走子相关函数, 非仅 thunk 区
  
走子逻辑函数族 (32 位原版):
  - 0x39f20 (执行器入口) → 0xb67ec (标志 setter)
  - 0xb6808 (验证: 边界 + rank)
  - 0x55d40 区 (事件分发)
  需全族扫描 rank 比较, 非单点
```

### 5.2 rank 编码对照方法 (可复用)
```
32 位 rank 比较提取:
  1. 找走子验证函数 (边界检查 + rank cmp)
  2. 提取 cmp rX, #N 的 N 值
  3. 对照 64 位 rank_of 编码 (junqi.h)
  
风险: 32 位 rank 编码可能 = 实际等级 (1-9) 或 红方 +0xc 后值
     64 位 src_rs 已有 "红方 = 实际+0xc" 口径 (rules.c:1210)
     → 需确认 32 位 cmp 值是否含 +0xc 偏移
```
