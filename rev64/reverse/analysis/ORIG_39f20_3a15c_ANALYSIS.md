## 一、0x39f20 函数实证 (★ 纠正 64 位注释)

### 函数特征

- bl 目标: 0x32a2c / 0xafb7c / 0xafb88 / 0xb67ec

## 二、0x3a15c 区实证 (坐标比较代码)

### 关键指令
```
3a15c:  ldrsb r2, [r4, r7]   ← 读有符号字节 (rank?)
3a15e:  ldrsb r1, [r4, r6]   ← 读有符号字节 (rank?)

3a162:  adds r3, r3, r2      ← r3 = r2 * 5 (数组索引?)

### 功能推测
- **坐标/rank 数组访问 + 字段读写**
- `ldrb/strb` = 字节数组 (可能是 60 格棋盘 rank 数组)
- `+128` 偏移 = 对象布局 (非直接棋盘索引)
- **非评分逻辑** (无比较分支, 纯数据搬运)

## 三、★ 评分逻辑最终结论 (诚实边界)

### 实证结果
| 地址 | 实证功能 | 评分特征 |
|------|----------|----------|
| 0x39f20 | 短函数, 读对象 +168/164 | ❌ 无 1000/900/800 常量 |
| 0x3a15c | 坐标/rank 数组访问 | ❌ 无比较分支 |
| 0x55d40 区 75 thunk | 析构/setter/虚函数分发 | ❌ 无 rank 比较 |
| 0x557d4 | getter thunk (读 +132) | ❌ 非评分 |

### 结论
1. **32 位原版无集中 AI 评分表** (64 位 ai_score 的 1000/900/800/700/2/1 在 32 位未找到)
2. **单步贪心实现分散**: 可能在走子执行器 (0x39f20 区) + 事件 handler (0x55d40 区) 内联
3. **64 位 ai_score 是简化实现**: 评分表是正向**设计**, 非 32 位地址对齐
4. **64 位 rules.c 注释 "对齐原版 0x39f20/0x55d40 单步贪心"** = **语义对齐** (单步贪心无价值维度), 非地址对齐

### 给正向会话 (AUD_ALIGN_R16 追加)
- rules.c:1213 注释 "对齐原版 0x39f20/0x55d40 单步贪心无价值维度" **口径正确** (语义对齐)
- 但 1216/1219/1224 "原版 0x55d40 handler 实证单步评分" **需改** → "原版 0x55d40 区无集中评分表, 单步贪心分散在执行器+handler"
- ai_score 评分表 (1000/900/800/700/2/1) 标注为 "正向设计, 非 32 位地址对齐"

## 四、教训固化

### 4.1 地址对齐 vs 语义对齐
```

实际:
  - 0x39f20 区 = 走子执行器 (语义)
  - 64 位 jq_try_move = 走子执行 (语义对齐, 非地址对齐)
  
注释规范:
  "对齐原版 0x39f20 区语义 (走子执行器)" ← 明确语义
  "ai_score 评分表为正向设计, 原版单步贪心无价值维度" ← 明确设计意图
```

```
