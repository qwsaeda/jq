# 讲义通俗化改写规范(用户要求:讲明白痛点 + 通俗易懂 + 为什么这样做 + 篇幅够)

## 核心原则

用户反馈:之前的讲义"内容太少,跟原章节差很多"。要求:
1. **每章 250-400 行**(原书每章 2000-4000 字,课程要"提炼但够用",不能太薄)
2. **讲明白痛点在哪 + 为什么这样做 + 怎么做 + 军棋怎么验证**
3. 通俗易懂:技术名词第一次出现加括号大白话解释,多用生活类比

## 每章统一结构(必须包含)

```
# 第N章 标题
> 课程配套 + 军棋靶机

## 痛点:为什么 X?(2-4 个痛点,每个:大白话卡点 + 为什么卡 + 不解决会怎样)

## 为什么这样做:方案动机(大白话 + 生活类比,讲清楚"为什么要这么做而不那样做")

## N.1 第一小节(展开讲,含代码 + 注释 + 军棋对照)
## N.2 第二小节(...)
## N.3 第三小节(...)
(按原书章节展开,3-6 个小节,每节 30-60 行)

## 军棋实战验证(用军棋 libjunqi.so 真实数据/卡点验证本章原理)

## 本章小结(一句话版,3-5 行)

## 配图
- ...
```

## 篇幅与深度要求

- **每章 250-400 行**(原书每章内容量,课程"提炼但保留深度")
- **每个小节 30-60 行**(不能只 5-10 行的"梗概")
- **代码段要完整可运行**(带注释,不是片段)
- **表格加"大白话解释"列**
- **军棋实测数据保留**:12 init_array / 5312 RELATIVE / 214 PLT / 6 GLOB_DAT /
  14 JNI 入口 / 7 依赖库 / 0x43ed8 / 0x159880 / 0x233e1 / unicorn2 / redroid / §124 三项阻塞

## 保留项(不改)

- 末尾「配图」段的 png/mp4 路径
- 军棋实测数据(见上)
- 红线引用(§R6 / §122 / §124)

## 通俗化技巧

- 技术名词第一次出现加括号大白话:
  - `.so` = shared object(共享对象,可被多个程序复用的代码块)
  - `ELF` = 可执行与可链接格式(二进制文件的"骨架描述")
  - `mmap` = 把文件内容映射到内存(虚拟地址空间)
  - `PLT/GOT` = 过程链接表/全局偏移表(函数调用的"跳板 + 电话簿")
  - `std::vector` = C++ 动态数组(自动扩容的容器)
- 多用类比:毛坯房/电话簿/钥匙/家具/外卖窗口/行车记录仪
- 每个"为什么这样做"配一个生活场景
