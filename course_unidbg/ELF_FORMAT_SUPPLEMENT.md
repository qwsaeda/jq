## 二、ELF 格式全字段（课程 ch04 补，取《二进制分析实战》第 2 章）

**课程通用**：跑任何 so（壳/非壳）都要读 ELF 段属性。军棋 ch04 只讲"9 个 PT_LOAD"，缺全字段。

### 2.1 ELF 头部全字段（`e_ident` 16 字节 + 全结构）
```c
typedef struct {
  unsigned char e_ident[16];  // 幻数 0x7f ELF + EI_CLASS(32/64) + EI_DATA(大小端) + EI_OSABI
  uint16_t e_type;            // ET_REL/ET_EXEC/ET_DYN/ET_CORE
  uint16_t e_machine;         // EM_ARM=40 / EM_AARCH64=183
  uint32_t e_version; uint64_t e_entry;
  uint64_t e_phoff; uint64_t e_shoff;
  uint32_t e_flags;
  uint16_t e_ehsize; uint16_t e_phentsize; uint16_t e_phnum;
  uint16_t e_shentsize; uint16_t e_shnum; uint16_t e_shstrndx;
} Elf64_Ehdr;
```

### 2.2 节全谱系（`SHDR`，取《二进制分析实战》2.3）
| 节 | 含义 | 课程通用 | 军棋 |
|---|---|---|---|
| `.text` | 代码（r-x） | ✅ | 1MB 明文（非壳） |
| `.rodata` | 只读数据（r--） | ✅ | 118KB 明文（静态=运行时 0/118832 不同） |
| `.data` | 已初始化可写（rw-） | ✅ | 28288B（`jq_rel_data.h` 拷贝） |
| `.bss` | 未初始化可写（rw-，文件 0 字节） | ✅ | 0x15be80 起（影子内存清零） |
| `.plt`/`.got`/`.got.plt` | 跳板/全局偏移表（**延迟绑定**） | ✅ | 214 PLT + 6 GLOB_DAT |
| `.init_array`/`.fini_array` | 构造/析构函数 | ✅ | 12 个 init_array（全通） |
| `.dynamic` | 动态链接信息（DT_NEEDED/DT_RELATAG） | ✅ | 7 依赖 + 5312 RELATIVE |
| **`PT_GNU_RELRO`** | **重定位后锁 `.got`/`.data` 只读（防 GOT 覆盖）** | ✅（加固检测点） | `.got` rw-（未锁，unidbg 未跑完重定位） |

**`.got` 为何 rw- 不 r--（大白话）**：
- `.got` = "外部函数/全局变量的门牌号"
- **加载时**（dlopen 重定位）：linker 要**写** `.got`（填 libc/GL 函数地址）→ 必须 `rw-`
- **重定位完成后**：`PT_GNU_RELRO` 段把 `.got` 改 `r--`（锁，防 GOT 覆盖攻击）
- **壳 so**：壳存根解密后 `.got` 才填真值（脱壳后 `.got` 才可用）

### 2.3 程序头全字段（`PHDR`，取《二进制分析实战》2.4）
| `p_type` | 含义 | 课程通用 | 军棋 |
|---|---|---|---|
| `PT_LOAD` | 可加载段 | ✅ | 9 个（RX + RW） |
| `PT_DYNAMIC` | 动态链接信息 | ✅ | 有 |
| `PT_INTERP` | 解释器（`/system/bin/linker`） | ✅（真机走它，unidbg 走简化 Linker 不走） | 有（unidbg 不用） |
| **`PT_GNU_RELRO`** | **RELRO 段（重定位后锁只读）** | ✅（加固检测点） | `.got` rw-（未锁） |
| **`PT_GNU_STACK`** | **栈 NX 位（rwx / rw-）** | ✅（NX 检测点） | 栈 NX（不可执行） |
| **`PT_NOTE`** | 自定义段（`.note.gnu.gold-version` 等） | ✅（自定义段实例） | 有 |
| **`PT_PHDR`** | 程序头自引用 | ✅ | 有 |

**自定义段 = ELF 格式层（PHDR/SHDR 新增段），花指令 = 指令层（`.text` 内插指令）——两层不同**（见下节）。

## 三、花指令 vs 自定义段（课程 ch04 新增 4.x，区分两层）

**课程通用**：跑混淆/加壳 so 要区分"指令层混淆"和"ELF 格式层自定义段"（两者处理手段不同）。
**军棋靶机**：军棋 so 明文非壳，**没有花指令/自定义混淆段**，但课程该讲清区分（原书样本有壳）。

| 维度 | 花指令（OBSO） | 自定义段（ELF 格式层） |
|---|---|---|
| **所在层** | **指令层**（`.text` 里塞无意义指令/不透明分支） | **ELF 格式层**（`PHDR`/`SHDR` 的段，如 `PT_GNU_RELRO`/`PT_NOTE`） |
| **目的** | 反汇编器乱（让 IDA/Ghidra 解不出正确基本块） | 段属性/权限/重定位（OS 加载器用） |
| **处理手段** | **递归反汇编 + 控制流分析**（Capstone 递归跟控制流，处理假分支） | **读 PHDR/SHDR**（readelf 看段属性，跟指令无关） |
| **军棋现状** | ❌ **无**（军棋 `.text` 熵 7.10 正常，反汇编直接可做） | ✅ 有（9 个 PT_LOAD + `PT_DYNAMIC`/`PT_INTERP`/`PT_PHDR`/`PT_NOTE`，全标准） |
| **跟对方的关系** | **花指令不改 ELF 段结构**（只在 `.text` 内插指令，不改 PHDR/SHDR） | 自定义段是**新增 PHDR/SHDR**（跟 `.text` 内指令无关） |

**"不透明分支"（《二进制分析实战》第 8 章脚注 3）**：混淆器用"始终为真/始终为假"的判定代码构造分支，
让静态反汇编器误判基本块边界——**这是花指令的高级形式，也不是自定义段**。
**课程通用价值**：跑壳/混淆 so 时，Capstone 递归反汇编 + 控制流分析（第 8 章 6.4.2）处理不透明分支；军棋非壳，跳过。

**区分方法**：`readelf -l`（看 PHDR 段乱 = 自定义段）vs `objdump -d`（看指令乱 = 花指令）。

## 四、重定位全谱系 + 延迟绑定（课程 ch06 补，取《Linux 二进制分析》第 2 章 2.5）

**课程通用**：unidbg Linker 填重定位（课程 ch06 核心），全谱系 + 延迟绑定机制。

### 4.1 重定位类型全谱系（`R_ARM_*`）
| 类型 | 含义 | 课程通用 | 军棋 |
|---|---|---|---|
| `R_ARM_NONE`(0) | 不重定位（占位/对齐） | ✅ | 有（段内对齐） |
| `R_ARM_32`(1) | 绝对地址（`[S+A]`） | ✅ | 有（`.data` 指向 `.rodata` 的绝对指针） |
| `R_ARM_PC32`(2) | PC 相对（`[S+A-PC]`） | ✅ | 有（`ldr rX,[pc,#N]` 常量池引用） |
| `R_ARM_RELATIVE`(3) | 相对重定位（加 load_base） | ✅（**unidbg Linker 核心**） | 5312 个（全通） |
| `R_ARM_ABS32`(4) | 绝对 32 位 | ✅ | 有 |
| `R_ARM_GLOB_DAT`(204) | 全局数据重定位（GOT 槽） | ✅ | 6 个（全通） |
| `R_ARM_JUMP_SLOT`(207) | PLT 跳板（**延迟绑定**） | ✅（**unidbg Linker 核心**） | 214 个（全通） |
| `R_ARM_IGN`(255) | 忽略（占位） | ✅ | 有 |

### 4.2 延迟绑定（`.plt`/`.got`/`.got.plt`，取《二进制分析实战》2.3.4）
**"延迟绑定" = 首次调用外部函数时才填 `.got.plt`（不是 dlopen 时全填）**：
```
首次调 libc.foo()：
  .plt[foo] → .got.plt[foo]（空）→ 跳 _dl_runtime_resolve（linker）
  → 查 .dynsym 解析 foo 真地址 → 填 .got.plt[foo]
  → 二次调 foo：直接 .got.plt[foo]（已填，不跳 linker）
```
**课程通用价值**：unidbg 模拟时全填（AndroidResolver 直接解析符号填 `.got.plt`，不需要真"首次跳 linker"）。
**军棋 214 个 PLT**（JUMP_SLOT）就是延迟绑定槽。

**"军棋 3 类重定位为什么够"（大白话）**：
- `R_ARM_RELATIVE`（5312）= "所有要加 load_base 的相对指针"（`.got`/`.data` 内部指针）
- `R_ARM_JUMP_SLOT`（214）= "所有外部函数调用"（延迟绑定 PLT 跳板）
- `R_ARM_GLOB_DAT`（6）= "所有外部全局变量"
- `R_ARM_32`/`R_ARM_PC32`/`R_ARM_ABS32` 在军棋 `.so` 里**已重定位完**（so 文件里的值是真值，不靠 dlopen 再填）→ unidbg 不用管
- **18 个 `.text` 常量池**不是重定位（是 `ldr rX,[pc,#N]` 读的内嵌常量，跟重定位类型无关，只有 dlopen 才填值）

## 五、加壳器 + 脱壳器（课程 ch27 补，取《二进制分析实战》第 9 章 + 《Linux 二进制分析》第 5 章）

**课程通用**：unidbg 跑壳 so 的**前置**——壳 so 先脱壳才能补环境（壳存根解密后才跑原代码）。
**军棋靶机**：军棋 so 明文非壳，**加壳/脱壳用不上**，但"加壳 vs 非壳判断"用得上。

### 5.1 加壳器（packer）原理
```
加壳二进制文件的创建 + 加载过程：
  普通 so（代码段+数据段）→ 加壳器把代码/数据"打包"进压缩/加密数据区
  → 生成新 so（壳存根 + 加密数据区）
  加载时：
  壳存根（PT_LOAD 段，入口）→ 解密代码/数据区 → 映射到 PT_LOAD 指定地址
  → 跑原代码（OEP = 原始入口点）
```
**"存根"（《Linux 二进制分析》5.3）**：壳的用户层执行组件——解密 + 映射原代码 + **开反调试/反模拟模式**（提高逆向门槛）。
**课程通用价值**：跑壳 so 时，存根的反模拟检测（查"是不是在 Unicorn/Frida 里跑"）= 课程 ch27 反检测 8 维度。

### 5.2 脱壳器原理（Pin DBI + OEP 跳转检测，《二进制分析实战》9.5.2）
**脱壳器 = 逆向"加壳"过程**（用 Pin 动态插桩跟踪到 OEP 跳转，dump 解密后的代码）：
```
Pin DBI 引擎 → 监控所有指令 → 检测"向一次性写内存区（OWMR）的间接控制流跳转"
  → OWMR = 加壳时存根解密代码写入的内存区（解密后写一次）
  → 间接跳转 OWMR = "跳到 OEP（原始入口点）" = 脱壳完成信号
  → dump OEP 周围连续字节 = 脱壳产物（解密后 .text）
```
**课程通用价值**：跑壳 so 先脱壳（dump 解密后 `.text`），再 unidbg 补环境（否则 unidbg 读壳存根读不出原代码）。
**军棋跳过**（军棋非壳，反汇编直接可做，不需脱壳）。

### 5.3 "加壳 vs 非壳判断"（课程通用 + 军棋用上）
**判断 so 是否加壳**（课程通用）：
| 判据 | 壳 so | 非壳 so（军棋） |
|---|---|---|
| `.text` 熵 | 高熵（加密态，>7.5） | **7.10（正常机器码）** |
| `.rodata` 静态 vs 运行时 | 不同（自解密例程跑完才明文） | **0/118832 不同（静态=运行时，无自解密）** |
| 入口 | 壳存根（PT_LOAD 加密段） | 原入口 |
| `readelf -l` | 有加密数据段（非常规） | 全标准 9 段 |

**军棋 so 非壳证据**：`.text` 熵 7.10（正常机器码）+ `.rodata` 静态=运行时 0/118832 不同（无自解密）→ **反汇编直接可做**（`objdump` 出真实指令 + JNI 符号名）。

### 5.4 军棋 §124 三项阻塞 vs 壳特征（军棋靶机）
| §124 阻塞 | 是壳特征吗 | 军棋实际 |
|---|---|---|
| ① BL 解码 bug | ❌ 非壳（unicorn2 模拟器精度问题，非 so 自解密） | unidbg 的 bug，不是 so 的壳 |
| ② 数据与指令对齐对应缺口 | ❌ 非壳（C++ 运行时，堆对象运行时创建） | 翻译体 32→64 对象图错位 |
| ③ 288MB PROT_NONE mmap | ⚠️ 像壳但实际是 so 内的保护段 | unidbg mmap2 mock 失败（非壳自解密） |
| **结论** | **军棋 so 是明文非壳**（3 项阻塞全非壳特征） | 反汇编直接可做 |

**区别"重定位" vs "壳自解密"**（课程通用，易混淆）：
- **重定位**：linker 给 `.got`/`.data` 加 load_base（`.got` 槽从 0 变真地址），**不是壳**（标准 dlopen 行为）
- **壳自解密**：壳存根跑 XOR/decrypt 例程，把加密的 `.text`/`.rodata` 解密成明文（`PT_LOAD` 加密段 → 解密映射），**是壳**
- **军棋 18 个 `.text` 常量池"只有 dlopen 才填"** = **重定位**（linker 加 load_base），**不是壳自解密**（无 decrypt 例程）

## 六、二进制加固（课程 ch30 补，取《Linux 系统安全基础》第 6 章 6.1）

**课程通用**：unidbg 模拟时 mock 加固检测点（so 查 canary/relro/pie 作反检测维度）。
**军棋靶机**：军棋 so 是 PIE（18 常量用静态位移跟 PIE 关联），部分用上。

| 加固 | 原理 | 课程通用 | 军棋 |
|---|---|---|---|
| **Canary 栈保护** | 栈帧里塞随机值，溢出先改 canary（非返回地址）→ 检测到溢出退出 | ✅（反检测维度） | 军棋 so 编译时 `-fstack-protector`（有 canary） |
| **RELRO 部分**（`-z relro`） | 重定位后 `.got` 改只读（但 `.got.plt` 仍可写，延迟绑定） | ✅（加固检测点） | `.got` rw-（未锁，unidbg 未跑完重定位） |
| **RELRO 完全**（`-z relro -z now`） | 重定位时全解析（非延迟绑定）+ `.got` 全只读 | ✅ | 军棋走延迟绑定（PLT 214，部分 RELRO） |
| **PIE**（位置无关可执行） | 代码段随机基址（ASLR 配合）→ 攻击者难定位 | ✅（跟"18 常量静态位移"关联） | 军棋 so 是 ET_DYN（PIE，dlopen 时随机基址） |
| **NX**（`-z noexecstack`） | 栈不可执行（防 shellcode 注入栈） | ✅（NX 检测点） | 军棋栈 NX |
| **ASLR** | 堆/栈/共享库映射随机化 | ✅ | 军棋 so 在 ASLR 下基址随机 |
| **FORTIFY**（`-D_FORTIFY_SOURCE`） | 编译时把 `memcpy`/`sprintf` 换强检查版本 | ✅（反检测维度） | 军棋 so 编译时可能开 |

**军棋 "18 常量静态位移"跟 PIE/ASLR 的关系**（ch01 1.4.3★ 已讲，此处补强）：
- 军棋 so 是 **PIE**（ET_DYN，dlopen 时随机基址）+ **ASLR**
- 18 个 `.text` 常量池是 **PC 相对位移**（`ldr rX,[pc,#N]`）→ **注入值用静态位移**（`0x00138918` 类），**不用绝对地址**（基址随机，绝对值每次不同）
- 这就是 `jqt_mem.c` `g_jq_got_tbl` 用**静态位移**（跨进程通用）而非 redroid dump 绝对值的原因（§124z-3）

**课程通用价值**：跑加固 so 时，unidbg 要 mock 加固检测点（so 查"canary 在不在""relro 锁没锁""pie 基址对不对"作反检测），课程 ch30 反检测总结补这条。

## 七、二进制插桩 SBI/DBI + Capstone 反汇编（课程 ch15 补，取《二进制分析实战》第 8/9 章）

### 7.1 SBI vs DBI（《二进制分析实战》9.1.2）
| 类型 | 原理 | 课程通用 | 军棋 |
|---|---|---|---|
| **SBI（静态插桩）** | 永久改磁盘二进制（重写 `.text` 前 N 字节塞跳板/int3），不破坏引用 | ✅（unidbg Hook/Patch） | ⚠️ 军棋 `thumb2c_full.py` 翻译体用 SBI（改 `.text` 字节），插桩框架不用 |
| **DBI（动态插桩）** | 运行时监视指令流，插桩代码注入指令流（不改磁盘），Pin 引擎 | ✅（unidbg traceCode = 动态 trace） | ⚠️ 军棋 unidbg traceCode 是 DBI（动态 trace） |

**SBI 的 2 种实现（《二进制分析实战》9.2）**：
- **int3 方法**：函数前塞 `int 3`（x86）/断点指令 → 调试器断在插桩点 → 跳板（trampoline）恢复原指令继续跑。**缺点**：跟"正在调试"的程序不兼容
- **跳板方法**（trampoline）：复制原代码到跳板区，**跳板区里插桩**（原代码不动），用 `jmp` 把原代码重定向到跳板副本。**优点**：不破坏原引用（原代码地址不变）

**课程通用价值**：unidbg Hook（ch15）= "跳板方法"（改 `.text` 前 N 字节塞跳板，原代码复制到 trampoline）——跟《二进制分析实战》第 9 章原理一致。

### 7.2 Capstone 自定义反汇编（《二进制分析实战》第 8 章）
**军棋 `thumb2c_full.py` 真源 = Capstone 反汇编**（第 8 章 8.2.2 线性 + 8.2.4 递归）：
| Capstone 模式 | 用途 | 课程通用 | 军棋 |
|---|---|---|---|
| **线性反汇编**（8.2.2） | 逐条指令顺序解（快，但控制流分支可能解错） | ✅ | `load_insns`（逐条解 7428 函数） |
| **递归反汇编**（8.2.4） | 跟控制流递归解（准，能处理跳转/函数调用） | ✅（跑混淆 so 必备） | `translate_func`（可达集分析，递归跟 bl/blx） |
| **代码混淆反汇编**（8.1.1） | 处理不透明分支（混淆器塞的假分支） | ✅（跑混淆 so 必备） | ❌ 军棋非壳，跳过 |

**课程通用价值**：自写反汇编工具（`thumb2c_full.py` 类）= Capstone 线性 + 递归，军棋红线"JNI 入口是 Thumb 奇地址，translate_func 起点要 bisect 对齐到最近偶指令"= 递归反汇编的控制流处理。

### 7.3 动态污点分析 / 符号执行（《二进制分析实战》第 10-13 章）
| 技术 | 用途 | 课程通用 | 军棋 |
|---|---|---|---|
| **动态污点分析**（libdft，第 10-11 章：污点源/槽/传播） | 跟踪"输入→输出"数据流（哪字节影响哪字节） | ✅（课程讲"数据流怎么追"，算法还原时污点跟踪） | ❌ 军棋 SPAK 已直接逆出（XOR+zlib），**跳过** |
