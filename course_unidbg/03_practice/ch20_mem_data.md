# 第20章 unidbg 实战：使用 unidbg 动态分析内存中的数据

> 课程配套：《unidbg 逆向工程：原理与实践》陈佳林（机工社 2024）
> 本地对照：军棋 32 位 so 的 `.rodata` 动态验证

## 痛点：为什么"静态看 IDA"不够，还要"动态跑 unidbg"？

你用 IDA 看军棋 so 的 `.rodata`（只读数据段，存字符串/常量），看到一堆字符串
（`Junqi.Move` / `Flip` / `Flag` / `Bomb` / `Eat` / `Dead`...）。但静态分析有三大坑。

### 痛点 1：字符串是"活的"还是"死的"？

IDA 静态看，不知道**运行时谁在读这个字符串、怎么读**。

- **大白话卡点**：`.rodata` 里躺着一堆字符串，你不知道哪些是"真被代码在用"，
  哪些是"编译留下的尸体"（死字符串）。
- **为什么卡**：军棋 `.rodata` 里的 `Junqi.Move`（走子事件名），可能是"真被用来
  发事件"，也可能是"废弃的死字符串"（代码里没人引用了）。静态看"它在"，
  不等于"它在跑"。
- **不解决会怎样**：按静态字符串清单去补环境/还原规则，可能补了一堆没人用的，
  漏了真正在用的——逆向方向跑偏。

### 痛点 2：字符串被"改过"怎么办？（军棋：恰好可证伪）

so 可能运行时**拼接 / 改写字符串**（比如把 `Junqi.Move` 拼成 `Junqi.Move.123`），
或**自解密**（`.rodata` 里存的是密文，运行时解密成明文）。静态看是"密文 / 半截
字符串"，运行时才是"真明文"。

- **大白话卡点**：你静态看到的值，运行时可能已经是另一个值了。
- **为什么卡**：壳/自解密例程会在 dlopen 后改 `.rodata` 内容，静态文件与运行时
  内存对不上。
- **不解决会怎样**：按静态值判断"这是壳/这不是壳"可能直接判错——**军棋就踩过
  这个坑**：之前误判"`.rodata` 加密、dlopen 自解密"（错的）。

**军棋的交叉验证（这章的核心价值）**：`.rodata` 静态 dump 与运行时 dump
**逐字节相同（0/118832 不同）** → 无自解密例程 → **军棋 so 不是壳**。
唯一高熵点 0x138000（熵 7.87）在 `.rodata` 只读数据段内，是压缩/索引表
（值非有效地址），**非加密代码**。这章正是用来"用动态数据证伪静态误判"。

### 痛点 3：配置值指向哪？

`updateUrl` / `statHost` / `cfgHost` 在 `.rodata` 里是字符串，但**运行时是否被
覆盖**？so 可能启动时从服务器拉新 URL 覆盖它。静态看是"默认值"，运行时才是"真值"。

- **大白话卡点**：静态读到的配置值是"出厂默认"，运行时可能被远程配置改写。
- **为什么卡**：服务器下发的配置在 `.data`/堆上，不在 `.rodata`，静态文件里看不到。
- **不解决会怎样**：拿静态默认值当运行时值用，判断"它连的是哪个服务器"会错。

## 为什么这样做：静态定位 + 动态验证（交叉验证）

思路：**IDA 静态看到"有这么个字符串"，unidbg 动态跑"so 真的读了它、读到的是啥"。**
两相对照，确认"这个字符串是真用的，不是死代码"。

类比：IDA 是"看地图"（标了"桥"在这），unidbg 是"真走一遍"（走过去看桥在不在）。
地图上标了"桥"，走一遍才知道桥是真的还是画错。

**预判追问："动态跑一下不就把静态值都覆盖了？直接信动态不就行了？"** 不行，
两个方向都要信：
1. 动态**读不出**的值（18 个 `.text` 常量池，dlopen 重定位后才填，unidbg 里
   `.got` 槽为零）——静态同样读不出，两条路都断，只能 redroid dump 72B。
2. 动态**读到的**值要回头跟静态对照——军棋 `.rodata` 0/118832 不同这个结论，
   正是"动态 dump 回来的字节 vs 静态文件字节"逐字节比出来的。只信动态 = 失去了
   "证伪壳"的能力。

**军棋的特殊价值**：军棋 `.rodata` 静态 = 运行时（逐字节相同），
这章动态验证的目的 = **证实"军棋 so 不是壳"这个结论**（之前误判过"加密壳"）。
交叉验证还顺带确认 `.text` 熵 7.10（正常机器码）+ 无 `.text` 自解密例程。

## 20.1 环境搭建（军棋 unidbg 环境）


> **本节核心**：
> 1. 军棋 unidbg 环境（unicorn2 + 7 依赖 + 挂桩 GL）
>
> **本节难点**：
> 1. 12 init_array + 5312 RELATIVE + 214 PLT + 6 GLOB_DAT 全通（红线 §R6）
> 2. 环境搭建是「能加载」前提
> 3. 7 依赖含 liblog，2 GL 库挂桩（无真 GPU）

军棋 32 位 so 的 unidbg 环境（红线 §R6）：
```java
// 1. unidbg/unicorn2 后端(修 PC off-by-2 bug)
AndroidEmulator emulator = AndroidEmulatorBuilder.for32Bit()
        .backend(Backend.UNICORN2).build();
// 2. AndroidResolver(23) 提供 5 个系统库(libc/libstdc++/libm/liblog/libdl)
//    军棋 7 个 DT_NEEDED 里的前 5 个
emulator.getMemory().setLibraryResolver(new AndroidResolver(23));
// 3. 挂桩 libGLESv1_CM / libGLESv2(无真 GPU,军棋 7 依赖里的 2 个 GL 库)
emulator.getMemory().symbolResolver().resolve("glGetError").when((h) -> 0L);
// 4. 加载军棋 so(跑 12 init_array + 重定位)
VM vm = emulator.createDalvikVM(new File("junqi.apk"));
DalvikModule dm = vm.loadLibrary(new File("lib/armeabi/libjunqi.so"), true);
```
**环境验证**：12 init_array + 5312 RELATIVE + 214 PLT + 6 GLOB_DAT 全通（军棋实测）。

- Hook `0x3a15c`（走子执行）看吃子结果 → 还原"吃没吃、谁死"

**不是原版汇编级逆向**（红线 §64 位 native 诚实边界）。原版走子判定 0x39e14 只判目标类型，

## 20.5 动态验证（unidbg 交叉验证军棋"非壳"结论）


> **本节核心**：
> 1. 交叉验证军棋「非壳」结论：.rodata 静态=运行时 0/118832 不同
>
> **本节难点**：
> 1. 高熵点 0x138000 是压缩索引表（非加密代码）
> 2. 「非壳」是军棋关键结论（纠正早期「.rodata 加密自解密」误判）
> 3. .rodata 唯一高熵点 0x138000（熵 7.87）值非有效地址，是压缩/索引表

```java
// 1. 静态:IDA 看到 .rodata 里有个 "Junqi.Move" 字符串
// 2. 动态:Hook 读字符串的指令,看 so 真的读了它
emulator.getBackend().hook(module.base + READ_STR_ADDR, (hook) -> {
    String s = hook.readString(hook.registers().r0());
    System.out.println("so 运行时读到: " + s);
    // 动态确认 "Junqi.Move" 真被用了(不是死字符串)
});
// 3. 交叉验证 .rodata 静态 = 运行时
byte[] staticRodata  = readFile("frida-dump/rodata_dec.bin");   // 静态 118832B
byte[] runtimeRodata = readMemFromSimulator(0x120bf8, 118832);  // 模拟内存读
boolean same = Arrays.equals(staticRodata, runtimeRodata);
// 军棋:same = true(0/118832 不同)→ 证 .rodata 不是加密壳
```
**军棋红线 §R6 的交叉验证结论**：
- `.rodata` 静态明文 = 运行时 dump 逐字节相同（0/118832 不同）
- **说明 `.rodata` 不是加密的**（之前"加密壳"判断是错的）
- 唯一高熵点 0x138000 是压缩/索引表（值非有效地址），**非加密代码**
- 整 so **无传统壳特征**（`.text` 明文熵 7.10 + `.rodata` 明文 + 无自解密例程）
## 20.6 逐环节"我们能干什么 / 不能干什么"

| 环节 | 能干什么（✓） | 不能干什么（✗） |
|---|---|---|
| **静态定位（IDA/objdump）** | `.rodata` 118KB 明文直接读：14 入口、1715 条字符串、`Junqi.Move` 交叉引用、0x138000 高熵点定性 | 看出"运行时真读了谁"（静态只证明"存在 + 被引用"，不证明"在跑"） |
| **动态 trace（unidbg Hook）** | 确认字符串"活/死"（Hook 读指令看 r0 指向）；交叉验证 `.rodata` 静态=运行时（0/118832）证非壳 | 拿到 18 个 `.text` 常量（dlopen 才填值，unidbg `.got` 零槽读不出，需 redroid dump 72B） |
| **交叉验证** | 证"无自解密例程"（军棋非壳的第一手证据） | 把"静态=动态一致"外推成"任意数据区都一致"（`.data`/堆是运行时写区，静态值只是初始值，不能比） |

## 本章小结（一句话版）

> IDA 静态看"有没有"，unidbg 动态看"用没用"（交叉验证）。
> 军棋 `.rodata` 静态 = 运行时（0/118832 不同）→ 证 `.rodata` 不是加密壳。
> 高熵点 0x138000 是压缩索引表（非加密代码），整 so 无壳特征。
> 字符串 / 配置 / 服务器值，静态看"存在"，动态看"真用"；
> 18 个 `.text` 常量两个方向都读不出，只能 redroid dump——动态验证也有边界。
> **军棋棋盘数据**（R3/REVERSE_NOTES 实测）：60 格十字形（每格 12B），38 子/方
> （rank 40 司令…rank 32 工兵 + 3 雷 + 1 旗 + 2 炸弹），走子判定 `0x39e14`、
> 走子执行 `0x3a15c`、布局校验 `0x6a3b0`——rank 小 = 强（1 司令 vs 9 工兵，1 胜）。
